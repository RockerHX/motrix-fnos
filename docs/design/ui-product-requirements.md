# Motrix fnOS UI 产品需求

> 状态：已确认，作为当前 UI 产品需求来源
> 决策基线：`1A 2B 3B 4B 5A`（2026-07-12）
> 事实来源：当前 `src/`、`docs/architecture.md`、`docs/api-contract.md`
> 边界：本文定义 UI 展示与体验需求，不替代架构、接口契约或开发计划。

## 1. 需求标记

- **[现状]**：当前源码已经实现，后续维护不得破坏。
- **[确认]**：用户已明确批准，但可能尚未进入当前实现。
- **[候选]**：只允许未来评估，未经明确排期不得实现。

## 2. 产品目标与用户

Motrix fnOS 是运行于 fnOS 的高频下载管理工具。主要用户在桌面 Web、手机浏览器或飞牛 App WebView 中创建下载任务、持续观察进度、处理异常并维护应用设置。

- **[确认]** 保留现有信息架构和业务流程；未经单独决策，不进行整体 UI 重设计。
- **[确认]** 独立浏览器和旧 fnOS 默认深色；支持的平台中，fnOS 桌面宿主跟随并监听明暗主题，飞牛 App WebView 只采用初始化主题。2026-07-22 完成的 logo 蓝色品牌色迁移不改变业务交互、信息架构或状态色语义。
- **[现状]** 当前视觉采用 fnOS 原生工具感：深海军蓝结构色、明亮蓝强调、高信息密度、低动效。
- **[现状]** 桌面端与移动端复用同一 Vue、Pinia、service、HTTP API 与 SSE 数据流。
- **[现状]** 支持简体中文与英文，所有布局必须容纳两种语言。

## 3. 信息架构

### 3.1 应用外壳

- **[现状]** 桌面端使用左侧导航、顶部工具栏和主内容区。
- **[现状]** 移动端使用单列内容、底部导航和适配触控的任务卡片；不复制业务状态。
- **[确认]** 导航分类依次为全部、下载中、已完成、回收站和扩展，默认进入“全部”；“全部”展示除回收站外的所有任务状态，不再提供“已停止”一级分类。
- **[现状]** 设置、帮助、关于和诊断为辅助入口；诊断可继续打开调试日志。
- **[确认]** 后续维护不得改变上述入口关系、分类语义或主流程。

### 3.2 响应式范围

- **[现状]** `< 768px` 使用移动布局；`768–1023px` 为窄桌面；`>= 1024px` 为完整桌面布局。
- **[确认]** 核心验收视口为 `1440×900`、`1024×768` 和 `390×844`。
- **[确认]** 移动端不得出现页面级横向滚动，底部导航、弹窗和内容必须考虑安全区。

## 4. 核心任务体验

### 4.1 任务列表与分类

- **[确认]** 桌面与窄桌面使用 Naive UI 纵向任务列表与克制分隔线，不使用状态装饰竖轨、常驻卡片阴影或逐项圆角边框；移动端保留单列触控卡片。
- **[现状]** 任务重点信息包括名称、URL、状态、进度、已下载/总大小、速度、ETA、分类和错误信息。
- **[现状]** 状态包括等待、下载中、暂停、完成、错误、已删除，以及磁链解析中和等待文件确认两种派生状态。
- **[现状]** 单任务按状态提供暂停、继续、确认文件、重新下载、删除、恢复、永久删除和详情操作。
- **[现状]** 删除支持选择是否删除下载文件；回收站可恢复任务或永久删除任务记录。恢复后统一保持暂停，保留文件时续传，已删除文件时从头下载。
- **[现状]** 种子和已确认磁链使用应用私有 metadata 恢复；磁链缺少 metadata 时重新解析并再次确认文件，旧种子 metadata 缺失时保持回收站记录并显示明确错误。
- **[现状]** 回收站支持确认后一键清空，并逐条复用永久删除任务记录能力；部分失败不回滚已成功删除的记录。
- **[现状]** 顶部工具栏支持创建、刷新，以及对当前可见任务执行批量暂停、继续和删除；不可执行时禁用。
- **[确认]** 数字数据应易于纵向扫描，使用表格数字；主次信息不得依赖颜色才能区分。
- **[确认]** 下载进度条独占稳定行宽；已下载量、剩余时间和速度使用互不挤压的固定信息槽，动态数值变化不得引起相邻内容位移。
- **[确认]** 任务分类使用前端分页，默认每页 20 条并可切换 20 / 50 / 100；普通批量操作只作用于当前页，清空回收站仍作用于全部回收站记录。
- **[确认]** 完成任务在 fnOS 宿主的卡片主操作区提供“在文件管理器中打开”；详情弹窗按后端上下文提供“打开文件”和“文件详情”。非单文件不显示“打开文件”，非宿主环境隐藏操作按钮并说明能力仅支持 fnOS 宿主。
- **[确认]** 任务详情默认展示语义化保存路径和文件路径；真实路径只放在折叠的“技术信息”区域并支持复制。每次宿主文件操作必须重新按任务 ID查询后端上下文，不直接使用任务列表缓存路径。

### 4.2 空状态

- **[现状]** 不同分类有对应标题和说明。
- **[现状]** 移动端空状态可显示“添加任务”和“打开设置”；桌面端主要依赖外壳工具栏和侧栏入口。
- **[现状]** 运行时退出或当前分类不允许创建时，创建操作禁用。
- **[确认]** 空状态是正常引导，不使用营销插画、夸张文案或错误页语气。

### 4.3 新建任务

- **[确认]** 弹窗包含链接下载、种子文件和磁力链接三种输入类型；单个与多个 HTTP/HTTPS 链接合并为同一多行输入，每行创建一个独立任务。
- **[现状]** 支持授权保存目录、立即开始/添加后暂停、分类、连接数、单任务限速和代理。
- **[确认]** 链接下载不提供自定义文件名；单条和多条链接统一调用批量创建能力，允许部分成功并展示失败条目。
- **[现状]** URL、磁链、种子文件和保存目录均有输入校验；授权目录加载中、加载失败或为空时必须有明确反馈。
- **[现状]** fnOS 桌面宿主和飞牛 App WebView 在设置页及新建任务无目录状态提供“添加授权目录”；选择器成功后必须等待后端官方查询确认，不能直接采用 SDK 返回路径。
- **[现状]** 授权取消不修改目录状态；普通用户新增授权显示需要 fnOS 管理员权限。刷新失败保留当前目录并明确提示状态可能过期。
- **[现状]** 独立浏览器、老 fnOS 或 SDK 初始化失败时不调用 App runtime 方法，只提示用户前往 fnOS 应用中心配置；设置页可以重新读取后端目录快照。
- **[确认]** 设置页和新建任务目录选择器显示当前语言对应的语义化路径，提交值仍是后端确认的真实路径；转换失败时继续显示真实路径，语言变化后重新请求展示数据。
- **[现状]** 提交期间关闭和重复提交受限；提交成功关闭弹窗，失败保留输入并展示错误。
- **[确认]** 三种输入必须保持在同一创建流程内，不增设另一套创建入口或静态假选项。

### 4.4 磁链文件确认

- **[现状]** metadata 解析后阻塞展示文件列表，默认全选，列出文件名/路径和大小。
- **[现状]** 用户必须至少选择一个文件；确认期间禁止关闭和修改选择，成功后开始真实下载。
- **[确认]** 桌面可使用紧凑表格；移动端必须提供可触控、可阅读且不横向溢出的文件选择表现。
- **[确认]** 必须清楚区分“正在解析”“等待确认”“确认提交中”和“已开始下载”。

## 5. 设置与辅助页面

### 5.1 设置

- **[现状]** 设置包含共享文件夹授权与刷新、默认下载目录、最大同时下载数、全局下载/上传限速、语言、公网反代 JSON-RPC Token 和独立局域网推送配置。
- **[确认]** 公网反代继续使用 `127.0.0.1:17081/jsonrpc` 和既有 Token；局域网使用固定 `17082/jsonrpc`、独立开关和独立 Token，两类凭据不得跨入口使用。
- **[确认]** 首次启用局域网入口时由服务端自动生成 Token，原文只在一次性弹窗显示；关闭入口保留 Token，轮换前二次确认并明确已有客户端将失效。
- **[确认]** 通过 RFC1918 IPv4 打开管理页时显示可复制的实际局域网地址；通过域名打开时显示需要替换 NAS 局域网 IP 的模板。目录仍只能选择 fnOS 已授权路径。
- **[确认]** 所有复制操作统一先使用现代 Clipboard API；只在安全顶层页面中才将临时输入框与 `execCommand("copy")` 作为可信降级。局域网 HTTP 或 fnOS 内嵌窗口中该 API 可能虚报成功，必须提示手动复制并保留可选择的内容。局域网 Token 失败后自动聚焦并全选原文，临时复制节点必须立即清理，任何 Token 均不得写入日志。
- **[现状]** 加载、保存、授权路径失败、空路径和未授权路径均影响提示及保存按钮状态。
- **[确认]** Motrix 保存语言优先于宿主语言；仅在没有本地偏好的登录前初始化时采用宿主语言，配置加载完成后始终由 Motrix 设置接管。

### 5.2 About

- **[现状]** 展示应用名、版本、维护者、目标架构、仓库链接、版本检测、匹配架构的 FPK 下载入口和最近更新历史。
- **[现状]** About 只保留 JSON-RPC 指南入口；完整指南使用独立窗格，避免与版本信息和更新历史混排。
- **[现状]** 版本检测覆盖未检查、检查中、有更新、已最新和不可用状态。
- **[确认]** 保留工具型信息层级，不改造成品牌宣传页。

### 5.3 Help

- **[现状]** 展示授权目录、下载设置、JSON-RPC、开机自启、回收站、扩展和诊断说明，并标识已启用、待实现、占位或排障属性；JSON-RPC 条目可打开独立指南。
- **[确认]** 不把“待实现”或“占位”说明伪装成已可操作功能。

### 5.4 Diagnostics 与调试日志

- **[现状]** 诊断展示应用版本、后端、通信、Aria2 进程和 RPC 状态，并提供引擎控制及刷新。
- **[确认]** 诊断分别展示 `17081` 回环反代入口和 `17082` 局域网入口、开关及各自 Token 配置状态，并提供独立指南入口；只展示状态，不显示 Token 原文。
- **[现状]** 管理面板可临时开启 Aria2 `debug` 详细日志 30 分钟，展示剩余时间与“下次启动生效”状态；恢复普通日志和自动到期都回到 `warn`，文件大小与数量上限始终不变。
- **[现状]** 诊断展示 Aria2、Rust 服务、生命周期和总日志占用，区分当前/历史字节数与文件数；总占用达到 80 MiB 时显示文字警告，刷新、导出、模式切换和清理后更新指标。
- **[现状]** 诊断提供脱敏 ZIP 导出与 Aria2 日志手动清理。清理需要二次确认，Aria2 运行中或状态未知时禁用并提示先停止引擎，不自动停止或唤醒引擎。
- **[现状]** 调试日志支持级别/分类筛选、重复条目折叠信息、刷新与“清空应用内调试记录”；界面明确说明该操作不会释放 Aria2 原生日志文件空间。
- **[现状]** 指标和日志覆盖加载、连接失败、空日志、操作中和错误反馈。
- **[确认]** 状态不能只用红绿颜色表达，必须配合文字或图标。

### 5.5 Web 管理鉴权

- **[确认]** 应用启动后必须先请求 `/api/auth/status`；确认访问权前不得挂载主窗口，也不得请求任务、设置、授权路径、调试日志、应用信息或 SSE。
- **[确认]** `setupRequired=true` 时显示首次初始化页；保护启用且未登录时显示登录页；保护关闭且取得匿名访问上下文后才进入主窗口。
- **[确认]** 初始化与登录使用独立全屏品牌卡片，不显示侧栏、任务名称、保存路径、版本检查、诊断信息或其他业务数据。
- **[确认]** 初始化表单包含密码和确认密码；登录表单只包含密码。密码规则与服务端一致：8–128 个 Unicode 字符，不自动裁剪，允许空格；界面明确推荐使用 12 个以上字符的密码短语。
- **[确认]** 表单支持回车提交、密码管理器、提交 loading、错误后重新聚焦和移动端软键盘；密码与 CSRF Token 不得进入持久存储。
- **[确认]** Session 失效、server 重启或业务 API 返回 401 时，立即卸载主窗口、停止 SSE、清空敏感前端状态并回到登录或初始化页。
- **[确认]** 多标签页使用不含敏感信息的浏览器消息同步退出、密码修改和保护状态变化；不得广播 Session、Cookie 或 CSRF Token。
- **[确认]** Web 管理保护关闭时，主窗口持续显示不可关闭的高风险横幅；设置页同时提供详细风险说明和重新启用入口。
- **[确认]** 设置页提供修改密码、启用/关闭 Web 管理保护和退出登录，鉴权配置变更必须输入当前密码。
- **[确认]** 公网 JSON-RPC Token 使用专用掩码读取和写接口；局域网 Token 仅在首次生成或轮换响应中返回一次，普通读取不得返回原文，弹窗关闭后前端立即清除原文。

## 6. 横向状态要求

现有页面和后续小范围前端修改应根据业务适用性覆盖以下状态：

| 状态 | 需求 |
| --- | --- |
| 默认 | 内容层级和主操作明确，不依赖 hover 才能发现核心操作 |
| Hover / Pressed / Focus | 桌面指针与键盘状态清晰；焦点环可见 |
| Loading | 保持布局稳定；优先局部骨架或按钮 loading，不用遮蔽全部内容 |
| Empty | 说明为什么为空及下一步；无可执行下一步时不展示假按钮 |
| Error | 就近说明问题并保留重试或修正路径 |
| Disabled | 同时通过对比度、形态和语义表达不可用原因 |
| Selected | 列表、导航、文件选择均有稳定的选中表现 |
| Runtime exiting | 禁止任务写操作，并提示服务正在退出 |

通用要求：触控目标至少 `44×44px`；正文不小于 `14px`；文本对比度满足 WCAG AA；动画尊重 `prefers-reduced-motion`。

- **[候选]** 独立“全部任务”“做种”“活动”“错误”导航分类及分类数量徽标。
- **[候选]** 右侧任务详情抽屉，以及连接、日志、文件等多标签详情面板。
- **[候选]** 打开目录、复制链接、任务编辑、下载任务用户名/密码、每任务备注。此处不包含必须实现的 Web 管理密码。
- **[候选]** 通知、开机自启、关闭窗口行为、任务完成动作和恢复默认设置。
- **[候选]** 可编辑 Aria2 路径/RPC 端口、数据库位置、日志级别等系统级设置。

## 8. 验收标准

- 所有现有操作、状态和响应式行为在相关前端修改后仍可用。
- 深色与浅色主题均保持既有信息结构、状态语义和可访问性；独立浏览器默认深色。
- 后续前端维护不改变导航、业务流程、API 数据流或 Pinia/service 边界。
- 候选功能在文档中与当前需求物理分区，不出现可点击的静态假功能。
- 中文和英文、长文件名、长 URL、长路径及真实非整数字段不会造成重叠或截断失控。
- 深色与浅色分别覆盖 `390×844`、`1024×768`、`1440×900`，同时检查中英文、长语义路径、真实路径折叠区和任务详情弹窗。
- 鉴权状态确认前不出现业务数据闪现或敏感 API 请求；首次初始化、登录、退出、Session 失效和保护关闭流程在桌面与移动端均可完成。
- 日志占用指标、详细模式倒计时、清理确认和错误反馈在 `1440×900`、`1024×768` 与 `390×844` 下不产生页面级横向滚动；移动端指标按单列展示。
- 诊断包下载、日志模式和清理只通过管理 Session HTTP API；外部 JSON-RPC 不获得对应入口，任何界面都不显示绝对日志路径或敏感凭据。
