# Motrix fnOS UI 产品需求

> 状态：已确认，作为当前 UI 产品需求来源
> 决策基线：`1A 2B 3B 4B 5A`（2026-07-12）
> 事实来源：当前 `src/`、`docs/architecture.md`、`docs/api-contract.md`、`docs/development-plan.md`
> 边界：本文定义 UI 展示与体验需求，不替代架构、接口契约或开发计划。

## 1. 需求标记

- **[现状]**：当前源码已经实现，重设计必须保留。
- **[确认]**：用户已明确批准，但可能尚未进入当前实现。
- **[候选]**：只允许未来评估，不进入首轮设计交付或代码实现。

## 2. 产品目标与用户

Motrix fnOS 是运行于 fnOS 的高频下载管理工具。主要用户在桌面 Web、手机浏览器或飞牛 App WebView 中创建下载任务、持续观察进度、处理异常并维护应用设置。

- **[确认]** 保留现有信息架构和业务流程，只系统重做视觉层级、密度、排版与组件表现。
- **[确认]** 同时提供深色与浅色主题；默认深色，只提供“深色 / 浅色”，不增加“跟随系统”。
- **[确认]** 视觉采用 fnOS 原生工具感：深炭灰、克制绿色、高信息密度、低动效。
- **[现状]** 桌面端与移动端复用同一 Vue、Pinia、service、HTTP API 与 SSE 数据流。
- **[现状]** 支持简体中文与英文，所有布局必须容纳两种语言。

## 3. 信息架构

### 3.1 应用外壳

- **[现状]** 桌面端使用左侧导航、顶部工具栏和主内容区。
- **[现状]** 移动端使用单列内容、底部导航和适配触控的任务卡片；不复制业务状态。
- **[现状]** 导航分类为下载中、已完成、已停止、回收站和扩展。
- **[现状]** 设置、帮助、关于和诊断为辅助入口；诊断可继续打开调试日志。
- **[确认]** 重设计不得改变上述入口关系、分类语义或主流程。

### 3.2 响应式范围

- **[现状]** `< 768px` 使用移动布局；`768–1023px` 为窄桌面；`>= 1024px` 为完整桌面布局。
- **[确认]** 核心验收视口为 `1440×900`、`1024×768` 和 `390×844`。
- **[确认]** 移动端不得出现页面级横向滚动，底部导航、弹窗和内容必须考虑安全区。

## 4. 核心任务体验

### 4.1 任务列表与分类

- **[现状]** 桌面与窄桌面展示纵向任务卡片列表；移动端展示单列触控卡片。
- **[现状]** 任务重点信息包括名称、URL、状态、进度、已下载/总大小、速度、ETA、分类和错误信息。
- **[现状]** 状态包括等待、下载中、暂停、完成、错误、已删除，以及磁链解析中和等待文件确认两种派生状态。
- **[现状]** 单任务按状态提供暂停、继续、确认文件、重新下载、删除、永久删除和详情操作。
- **[现状]** 删除支持选择是否删除下载文件；回收站永久删除只删除任务记录。
- **[现状]** 回收站支持确认后一键清空，并逐条复用永久删除任务记录能力；部分失败不回滚已成功删除的记录。
- **[现状]** 顶部工具栏支持创建、刷新，以及对当前可见任务执行批量暂停、继续和删除；不可执行时禁用。
- **[确认]** 数字数据应易于纵向扫描，使用表格数字；主次信息不得依赖颜色才能区分。
- **[确认]** 下载进度条独占稳定行宽；已下载量、剩余时间和速度使用互不挤压的固定信息槽，动态数值变化不得引起相邻内容位移。

### 4.2 空状态

- **[现状]** 不同分类有对应标题和说明。
- **[现状]** 移动端空状态可显示“添加任务”和“打开设置”；桌面端主要依赖外壳工具栏和侧栏入口。
- **[现状]** 运行时退出或当前分类不允许创建时，创建操作禁用。
- **[确认]** 空状态是正常引导，不使用营销插画、夸张文案或错误页语气。

### 4.3 新建任务

- **[确认]** 弹窗包含链接下载、种子文件和磁力链接三种输入类型；单个与多个 HTTP/HTTPS 链接合并为同一多行输入，每行创建一个独立任务。
- **[现状]** 支持授权保存目录、立即开始/添加后暂停、分类、连接数、单任务限速和代理。
- **[确认]** 链接下载不提供自定义文件名；单条和多条链接统一调用批量创建能力，允许部分成功并展示失败条目。
- **[现状]** URL、磁链、种子文件和保存目录均有输入校验；授权目录加载中、加载失败或为空时必须有明确反馈。
- **[现状]** 提交期间关闭和重复提交受限；提交成功关闭弹窗，失败保留输入并展示错误。
- **[确认]** 三种输入必须保持在同一创建流程内，不增设另一套创建入口或静态假选项。

### 4.4 磁链文件确认

- **[现状]** metadata 解析后阻塞展示文件列表，默认全选，列出文件名/路径和大小。
- **[现状]** 用户必须至少选择一个文件；确认期间禁止关闭和修改选择，成功后开始真实下载。
- **[确认]** 桌面可使用紧凑表格；移动端必须提供可触控、可阅读且不横向溢出的文件选择表现。
- **[确认]** 必须清楚区分“正在解析”“等待确认”“确认提交中”和“已开始下载”。

## 5. 设置与辅助页面

### 5.1 设置

- **[现状]** 设置包含默认下载目录、最大同时下载数、全局下载/上传限速、语言和 JSON-RPC token。
- **[现状]** token 支持显示/隐藏、复制和安全随机生成；目录只能选择 fnOS 已授权路径。
- **[现状]** 加载、保存、授权路径失败、空路径和未授权路径均影响提示及保存按钮状态。
- **[确认]** 增加深色/浅色主题切换需求；默认深色，后续通过现有 `/api/ui-preferences` 持久化，不新增平行业务状态。
- **[确认]** 主题切换应即时预览，保存失败时保持可理解的错误反馈；具体接口变更在代码实施前同步更新 API 契约。

### 5.2 About

- **[现状]** 展示应用名、版本、维护者、目标架构、仓库链接、版本检测、匹配架构的 FPK 下载入口和最近更新历史。
- **[现状]** 版本检测覆盖未检查、检查中、有更新、已最新和不可用状态。
- **[确认]** 保留工具型信息层级，不改造成品牌宣传页。

### 5.3 Help

- **[现状]** 展示授权目录、下载设置、开机自启、回收站、扩展和诊断说明，并标识已启用、待实现、占位或排障属性。
- **[确认]** 不把“待实现”或“占位”说明伪装成已可操作功能。

### 5.4 Diagnostics 与调试日志

- **[现状]** 诊断展示应用版本、后端、通信、Aria2 进程和 RPC 状态，并提供引擎控制及刷新。
- **[现状]** 调试日志支持级别/分类筛选、重复条目折叠信息、刷新与清空。
- **[现状]** 指标和日志覆盖加载、连接失败、空日志、操作中和错误反馈。
- **[确认]** 状态不能只用红绿颜色表达，必须配合文字或图标。

## 6. 横向状态要求

每个首批页面应根据业务适用性覆盖以下状态：

| 状态 | 需求 |
| --- | --- |
| 默认 | 内容层级和主操作明确，不依赖 hover 才能发现核心操作 |
| Hover / Pressed / Focus | 桌面指针与键盘状态清晰；焦点环可见 |
| Loading | 保持布局稳定；优先局部骨架或按钮 loading，不用遮蔽全部内容 |
| Empty | 说明为什么为空及下一步；无可执行下一步时不展示假按钮 |
| Error | 就近说明问题并保留重试或修正路径 |
| Disabled | 同时通过对比度、形态和语义表达不可用原因 |
| Selected | 列表、导航、文件选择均有稳定的选中表现 |
| Runtime exiting | 禁止任务写操作，并提示服务正在退出 |

通用要求：触控目标至少 `44×44px`；正文不小于 `14px`；文本对比度满足 WCAG AA；动画尊重 `prefers-reduced-motion`。

## 7. 首批设计交付

首批 Stitch/Figma 必须覆盖：

1. 桌面任务列表（`1440×900`、`1024×768`）。
2. 桌面任务空状态。
3. 移动任务列表（`390×844`）。
4. 新建任务弹窗（三种输入及校验/提交状态）。
5. 设置弹窗（含深浅主题）。
6. 任务详情与磁链文件确认状态。
7. About、Help、Diagnostics（含调试日志入口）。

## 8. 排除范围与未来候选

以下内容不是当前产品需求，不得出现在首轮设计或代码实施中：

- **[候选]** 搜索框、任务行右键菜单、底部全局速度/连接状态栏。
- **[候选]** 独立“全部任务”“做种”“活动”“错误”导航分类及分类数量徽标。
- **[候选]** 右侧任务详情抽屉，以及连接、日志、文件等多标签详情面板。
- **[候选]** 打开目录、复制链接、任务编辑、用户名/密码、每任务备注。
- **[候选]** 通知、开机自启、关闭窗口行为、任务完成动作和恢复默认设置。
- **[候选]** 可编辑 Aria2 路径/RPC 端口、数据库位置、日志级别等系统级设置。

## 9. 验收标准

- 所有现有操作、状态和响应式行为均能在新设计中找到对应位置。
- 深色与浅色主题具有等价信息结构、状态语义和可访问性。
- 首轮不改变导航、业务流程、API 数据流或 Pinia/service 边界。
- 候选功能在文档和设计稿中与首轮需求物理分区，不出现可点击的静态假功能。
- 中文和英文、长文件名、长 URL、长路径及真实非整数字段不会造成重叠或截断失控。
