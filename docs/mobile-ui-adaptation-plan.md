# 手机端 UI 适配完成记录

> 更新时间：2026-07-05  
> 适用范围：飞牛 fnOS Web UI、飞牛提供的公网子域名入口、飞牛 App 内 WebView / 手机浏览器。  
> 状态：本轮开发已完成；本文保留为实现记录和回归清单，不再作为未来计划文档维护。长期架构边界仍以 `docs/architecture.md` 为准。

## 1. 背景

基础功能稳定后，手机端主要问题是桌面两栏布局直接压到窄屏：固定 220px 侧栏占据大部分宽度，任务表格、空态、浮动按钮、顶部工具栏和弹窗在飞牛 App WebView / 手机浏览器中容易被截断或横向溢出。

本轮目标不是缩放整页，而是在同一套 Vue Web UI、Pinia store、service、HTTP API 和 SSE 数据流下完成响应式适配。

## 2. 完成范围

- 移动端外壳：桌面保持两栏布局，`max-width: 767px` 切换为单列主内容 + 顶部栏 + 底部导航。
- 移动端导航：分类入口、设置、帮助和诊断在窄屏均可触达，当前分类状态保持同步。
- 任务展示：桌面继续使用 `NDataTable`，移动端使用任务卡片列表，复用同一任务 store 和操作组件。
- 空态与 Extensions：移动端压缩插画、间距和按钮布局，避免横向溢出。
- 创建任务：移动端改为近全屏/全屏体验，表单单列排列，保存目录下拉和提交/取消操作可达。
- 设置、帮助、诊断、日志弹窗：移动端单列、可滚动、操作区可达，长文案和 token 操作允许换行。
- 安全区与触控：使用 `100dvh`、safe-area 变量和不小于 44px 的主要触控目标。
- 国际化：中文和英文长文案均纳入移动端溢出检查。

## 3. 非目标

- 不实现原生 App UI。
- 不新增移动端专用前端工程、store、service、API 或 SSE 数据流。
- 不改变 FPK manifest、服务脚本、Rust server、Aria2 sidecar 或 HTTP/SSE 业务流。
- 不在本轮实现插件、批量下载、BT/磁力等未完成业务能力。

## 4. 实现策略

本轮采用 **一套源码、一套业务状态和 API，布局层响应式，复杂展示组件按桌面/移动拆分** 的策略：

- `layouts/` 负责桌面/移动外壳切换。
- `features/*` 内按业务领域拆分展示组件；信息结构明显不同的任务列表拆为移动端卡片展示。
- 业务操作继续复用现有 store/service，不在移动端复制状态。
- 纯尺寸、间距、排列变化优先使用 CSS media query。

## 6. 风险与后续注意事项

- Naive UI `NDataTable` 不适合作为手机端主展示；移动端应继续使用卡片列表。
- 飞牛 App WebView 可能有自带顶部栏和底部安全区，新增布局需继续保留 safe-area 处理。
- 不要把业务状态复制成移动端专用 store；移动端和桌面端必须共享现有 Pinia store、service 和 HTTP/SSE 数据流。
- 若后续发现飞牛 App WebView 有特殊注入样式或 viewport 行为，应单独记录实机现象，再决定是否补充平台侧文档或实机验证。
